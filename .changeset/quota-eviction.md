Evict paths when a cache nears its quota. A finalized publication that puts a cache over 90% of its quota now starts an `evict-cache` Workflow run: it evicts least recently used paths until the cache is back under 80%, but never one used within `eviction_min_age_days` (new setting, default 30 days; 0 turns quota eviction off). A path read during a run is kept, and pushes never wait for eviction. Set the age with `cf-nix-cache cache eviction <cache> <days>` or `eviction_min_age_days` in `PATCH /api/caches/{cache}/config`, and read the last run from `last_eviction` in cache responses. A daily run at 04:00 UTC now applies `retention_days` (moved out of garbage collection) and catches a missed quota trigger. Garbage collection now only deletes unreferenced objects; after a run it also prunes index and quota rows kept for retries once they are 7 days old, and upload allocations with their finished upload jobs. **Upgrading requires changes to `wrangler.jsonc`:** add the `evict-cache` workflow with binding `EVICT_CACHE`, class `EvictCacheWorkflow`, schedule `["0 4 * * *"]` and `limits.steps` 25000. See the template's `wrangler.jsonc`. Deploys fail until it is present.
